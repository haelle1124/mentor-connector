# Mentor Connector PRD

작성일: 2026-09-29 · 팀원 검토용 원본: Claude Docs 문서 (이 파일과 내용 동일, 댓글은 그쪽에서)

## 1. 개요

Mentor Connector는 비수도권 중·고등학생의 고민을 AI가 읽고, 그 고민을 잘 이해해 줄 대학생 선배를 1:1로 연결하는 웹서비스다.

**문제.** 지역 청소년은 수도권에 비해 진로 정보와 대학생 롤모델을 직접 만날 기회가 적다. 기존 과외 플랫폼(예: 김과외)은 과목과 수업을 기준으로 선생님을 연결한다. 그래서 "무엇을 고민하는지"보다 "무엇을 배울지"가 매칭 기준이 된다.

**해결.** 학생이 학년, 관심 분야, 고민을 입력하면 AI가 멘토의 전공, 경험, 멘토링 분야, 멘토링 스타일과 비교해 맞는 선배를 추천한다.

**차별점.**

- 과외 선생님을 찾는 AI가 아니라, 내 고민을 이해하고 도와줄 선배를 찾는 AI
- 정서적 지원: 멘토가 진로·학습 조언을 하면서 공감과 격려의 태도를 갖춘다. 학생이 원하는 멘토 스타일(차분히 들어주는 선배, 현실적으로 조언하는 선배, 밝게 응원해 주는 선배)을 매칭에 반영한다.
- 심리상담은 하지 않는다. 대학생 멘토가 전문 상담을 하는 것은 상담윤리에 맞지 않기 때문이다.

**레퍼런스.** [캠퍼스잇 | 내 고민을 아는 선배와 1:1 멘토링](https://mentoring.ajaschool.com/intro). 고민 기반 선배 매칭 구조는 같고, Mentor Connector는 AI 매칭과 공감형 멘토 스타일 매칭을 더한다.

## 2. 목표와 범위

10월 7일까지 "고민 입력 → AI 추천 → 멘토링 신청"이 끝까지 동작하는 시연용 웹 프로토타입을 배포한다. 별도 발표는 없다.

| 구분 | MVP (10/7) 포함 | MVP 제외 |
| --- | --- | --- |
| 학생 | 고민 입력폼, AI 추천 결과, 멘토링 신청 | 회원가입, 로그인, 결제 |
| 멘토 | 프로필 데이터(실제 2명 가명 + 가상 예시 6~8명) | 멘토 전용 화면, 대학생 인증, 활동비 |
| 멘토링 | 신청 내용 저장 + 완료 화면 | 실시간 채팅, 영상통화, 일정 예약 |
| 정서적 지원 | 멘토 스타일 매칭, 위기 표현 감지 시 전문기관 안내 | 심리상담 카테고리, 감정 기록 기능 |

**향후 확장 (파일럿·공모전).** 실제 멘토 수 확대, 멘토 화면(신청 목록 확인), 학생·멘토 연락 수단, 대학생 인증, 보호자 동의 절차를 검토한다.

## 3. 사용자 정의

| 사용자 | 대상 | 필요한 것 | MVP에서의 역할 |
| --- | --- | --- | --- |
| 학생 (주 사용자) | 비수도권 중1~고3 | 진로·전공·학습법·대학생활 고민을 이해하고 들어줄 선배 | 고민 입력, 추천 확인, 신청 |
| 멘토 | 우리 학교 출신 성균관대학교 재학생 | 자신의 경험이 맞는 후배와의 연결 | 프로필 데이터로만 존재 (화면 없음) |

**대표 시나리오.** 경북의 고2 학생이 "경영학과에 관심은 있는데 주변에 물어볼 사람이 없고, 성적이 떨어져서 불안하다"고 적는다. 차분히 들어주는 선배를 원한다고 고른다. AI는 비수도권 출신이고 경영학을 전공하며, 고2 때 성적 하락을 겪어 본 차분한 스타일의 멘토를 1순위로 추천한다.

## 4. 사용자 흐름

```
홈 → 고민 입력 → 위기 표현 검사 → AI 매칭(Gemini) → 추천 결과 → 멘토링 신청 → 신청 완료
                  (있으면 1388·109 안내)  (실패 시 백업 매칭)  (멘토 3명 + 추천 이유)
```

AI 호출이 실패해도 백업 매칭으로 추천 결과까지 이어진다. 위기 표현이 있으면 추천은 그대로 보여 주고, 그 위에 안내 박스를 함께 띄운다.

## 5. 기능 요구사항

화면은 4개(홈, 고민 입력, 추천 결과, 신청 완료)다. P0는 10/7까지 반드시, P1은 시간이 남으면 만든다.

| ID | 기능 | 상세 | 우선순위 |
| --- | --- | --- | --- |
| F1 | 홈 화면 | 서비스 한 줄 소개, "내 고민에 맞는 선배 찾기" 버튼 | P0 |
| F2 | 고민 입력폼 | 학년(중1~고3), 지역(비수도권 시·도), 관심 분야·전공(선택+직접 입력), 고민 유형(학습법·진로 탐색·전공 선택·대학생활, 복수 선택), 고민 자유 서술(필수, 20자 이상), 원하는 멘토 스타일 | P0 |
| F3 | AI 매칭 | 입력과 멘토 데이터를 AI에 보내 상위 3명과 추천 이유를 받는다 (6장) | P0 |
| F4 | 백업 매칭 | AI 호출이 실패하면 키워드·항목 점수로 상위 3명을 고른다 | P0 |
| F5 | 추천 결과 | 멘토 카드 3장: 가명, 전공·학년, 대표 경험, 멘토링 스타일, "왜 이 선배가 맞는지" 2~3문장, 가상 멘토는 "예시 멘토" 표시 | P0 |
| F6 | 멘토링 신청 | 멘토 카드의 "멘토링 신청하기" → 하고 싶은 질문 한 줄(선택) → 신청 기록 파일에 저장 | P0 |
| F7 | 신청 완료 | "선배에게 신청이 전달됐어요" 안내와 응원 문구 | P0 |
| F8 | 위기 표현 안내 | 고민에 위험 표현이 있으면 추천 결과 위에 1388·109 안내 박스 (8장) | P0 |
| F9 | 전체 멘토 둘러보기 | 추천과 별개로 멘토 목록 보기 | P1 |
| F10 | 신청 목록 보기 | 팀 확인용 신청 기록 표 (숨긴 페이지) | P1 |

## 6. AI 매칭 설계

AI API는 사전 데이터를 가져오는 용도가 아니라, 서비스의 "AI" 그 자체다. 학생이 자유롭게 쓴 고민 문장을 읽고 이해하는 일은 코드로 직접 짜기 어렵기 때문에 API가 맡는다. API가 없으면 단어가 일치하는지만 보는 키워드 매칭이 된다.

**API가 하는 일 (1회 호출).**

1. 고민 분석: "성적이 떨어져서 불안하다" 같은 문장에서 핵심 고민(학습 슬럼프, 진로 불확실)과 감정(불안)을 뽑는다. 단어가 달라도 뜻이 비슷하면 알아본다.
2. 멘토 비교: 분석 결과를 멘토 프로필 8~10명과 비교해 상위 3명을 고른다.
3. 추천 이유 작성: 멘토별로 "왜 이 선배가 맞는지"를 학생에게 따뜻한 말투로 2~3문장 쓴다.

**출력 형식.** 코드가 바로 읽을 수 있도록 JSON으로 받는다.

```json
{"recommendations": [{"mentor_id": "M01", "reason": "..."}, {"mentor_id": "M04", "reason": "..."}, {"mentor_id": "M07", "reason": "..."}]}
```

**프롬프트 원칙.**

- 멘토 목록에 없는 사람이나 경험을 지어내지 않는다.
- 진단·상담하듯 말하지 않는다 ("우울증이에요" 금지).
- 중학생도 이해할 수 있는 말로, 존댓말로 쓴다.

**백업 로직 (F4).** API 오류, 한도 초과, 응답 형식 오류 시 아래 점수로 상위 3명을 고르고, 추천 이유는 고정 문구를 쓴다.

| 비교 항목 | 점수 |
| --- | --- |
| 관심 전공이 멘토 전공과 같은 계열 | 3 |
| 고민 유형이 멘토링 가능 분야에 포함 (유형당) | 2 |
| 원하는 멘토 스타일 일치 | 2 |
| 고민 글과 멘토 경험 키워드 겹침 (단어당) | 1 |

## 7. 데이터 모델

데이터베이스 없이 파일 2개로 운영한다. 멘토는 `mentors.json`, 신청 기록은 `applications.csv`다.

**멘토 프로필 (`mentors.json`, 8~10명).** 실제 멘토 2명은 가명, 나머지는 가상 멘토로 `is_example: true`.

| 필드 | 예시 | 설명 |
| --- | --- | --- |
| id | M01 | 고유 번호 |
| alias | 박하늘 | 가명 |
| major | 경영학과 | 전공 |
| year | 2학년 | 학년 |
| hometown | 경북 | 출신 지역 |
| admission_story | 고2 때 성적이 떨어졌다가 학습법을 바꿔 회복 | 입시·진로 경험 (2~3문장) |
| topics | ["학습법", "전공 선택"] | 멘토링 가능 분야 |
| style | 차분히 들어주는 | 멘토링 스타일 (3가지 중 1) |
| intro | "나도 같은 고민을 했어요." | 한 줄 소개 |
| is_example | false | 가상 멘토 여부 |

**학생 입력.** 저장하지 않고 추천 동안만 화면 상태로 들고 있다: grade, region, interests, concern_types, concern_text, preferred_style.

**신청 기록 (`applications.csv`).** 신청 시각, 멘토 id, 학년, 지역, 고민 유형, 하고 싶은 질문. 고민 자유 서술 원문은 민감할 수 있어 저장하지 않는다. 이름·연락처도 받지 않는다.

## 8. 안전·윤리

정서적 지원은 멘토의 공감하는 태도까지만 다루고, 위기 신호는 전문기관으로 안내만 한다.

**위기 표현 안내 (F8).**

- 감지: 고민 자유 서술에 위험 키워드(예: "죽고 싶", "자해", "사라지고 싶")가 있는지 코드로 확인한다. AI가 없어도 동작한다.
- 표시: 추천 결과 맨 위에 안내 박스를 띄운다. 추천은 그대로 보여 준다.
- 문구 초안: "힘든 마음을 적어 줘서 고마워요. 지금 마음이 많이 힘들다면 전문 상담사와 이야기해 보세요. 청소년상담 1388, 자살예방상담 109 (24시간, 무료)"

**멘토 역할 범위.** 멘토는 경험을 나누고 응원하는 선배다. 진단, 치료, 심리상담은 하지 않는다. 이 문구를 입력폼 아래에 작게 표시한다.

**개인정보.** 이름, 연락처, 학교명을 받지 않는다. 고민 원문은 저장하지 않는다. 단, 추천을 위해 AI API로는 전송되므로 입력폼에 "입력한 내용은 AI 추천에만 사용돼요" 안내를 넣는다.

**파일럿 전 필수 (MVP 이후).** 미성년자 보호자 동의, 멘토 행동 가이드와 사전 교육, 위기 상황 시 멘토의 보고 절차.

## 9. 기술 스택과 일정

파이썬 하나로 화면·AI·배포를 끝내는 구성이다. 코드는 Claude Code로 작성하고 이 저장소(haelle1124/mentor-connector)에 올린다.

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 화면 | Streamlit (Python) | HTML·JS 없이 파이썬만으로 웹 화면 |
| 추천 AI | Gemini API 무료 등급 (Google AI Studio) | 무료 한도 있음. Claude·ChatGPT API는 사용량 과금 |
| 데이터 | JSON·CSV 파일 | DB 설정 불필요 |
| 배포 | Streamlit Community Cloud | GitHub 연결로 무료 배포 |
| 비밀 키 | Streamlit secrets | API 키를 코드에 넣지 않음 |
| 개발 도구 | Claude Code | PRD를 읽고 구현 |

무료 등급 조건은 바뀔 수 있어, 키를 발급받을 때 한도를 확인한다. Streamlit Community Cloud는 재배포나 재시작 시 서버 파일이 초기화될 수 있어 `applications.csv`는 시연용이다. 파일럿에서는 구글 시트 등 외부 저장소로 옮긴다.

## 10. 성공 기준과 미결 사항

배포된 주소에서 아래 항목이 모두 통과하면 MVP 완료다.

- [ ] 테스트 시나리오 5개(중학생 1, 고등학생 3, 위기 표현 1)가 모두 입력부터 신청 완료까지 오류 없이 동작

- [ ] 위기 표현 시나리오에서 1388·109 안내 박스가 표시됨

**미결 사항.**

- [ ] 실제 멘토 2명의 프로필 내용 수집 (가명 사용 동의 포함)
- [ ] 가상 멘토 6~8명의 전공 구성 (성균관대 학과 중 어떤 계열을 포함할지)

- [ ] 보호자 동의 방식 (파일럿 전)
